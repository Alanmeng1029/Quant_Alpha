# 复现 `2.分钟K线因子` 的 31 个 DolphinDB 因子为 Rust factor set `dos_minute_v1`

## 背景与目标

`2.分钟K线因子/` 下有 31 个 DolphinDB 脚本（SecurityID/DateTime/LastPx/Volume 口径），每个脚本产出一个 股票×交易日 的日频因子。目标：在 `crates/quant-minute-factor` 中按现有 candidates.rs / candidates_v3.rs 的既定模式，把 31 个因子全部复现为一个新的 factor set，复用现有 loader / MarketContext / plan_blocks / writer / manifest 基建。

## 总体设计决策

- **新 factor set**：`dos_minute_v1`，新模块 `crates/quant-minute-factor/src/dos_candidates.rs`，输出 31 列宽表，列名 `mf_dos_<dolphin函数名snake_case>`（如 `mf_dos_illiq_shortcut`、`mf_dos_prop_t_dis`）。
- **列映射**：`LastPx→close, OpenPx→open, HighPx→high, LowPx→low, Volume→volume_share, Amount→amount_cny`；因子 1 的 `TradeMoney=LastPx*Volume` 按 .dos 原式用 `close*volume_share` 复现（不用 amount_cny，保持公式忠实）。
- **时间窗映射**（minute_index 已确认：0=09:30, 120=11:30, 121=13:01, 237=14:57, 240=15:00）：
  - 标准因子（28 个）：`minute_index 0..=237`（对应 .dos 的 09:30–14:57）；
  - 因子 10/12/19：`0..=240`（对应 endTime=15:00）；其中 10/19 再按 `rank(TradeTime) between 5:239` 截取 index 5..=239。
- **股票池**：沿用现有 MarketContext 指数成分 universe（000300∪000905∪000852，point-in-time），不复制 .dos 的 `00%/30%/6%` 前缀粗筛（那是数据卫生过滤，Rust 端 loader 校验已覆盖等价目的）。`LastPx>0` 由 loader 现有校验保证。
- **修正 vs 保留**（每个偏差都写进 `formulas()` 与文档）：
  - 修正：因子 2 的 `deltas(LastPx)` 在 .dos 中无 `context by`（跨股票边界取到上一股票末根价），Rust 按 (股票,日) 分组求 deltas；
  - 保留 .dos 口径：因子 23 的 (ret−0.1)/0.2 不做 [0,1] 截断；因子 30 的 `last(LastPx)` 在按价排序后取=当日最高分钟收盘价（复刻此语义）；因子 5 文件头描述与代码不符时以代码为准（20日 mavg）。
- **跨日窗口语义**：DolphinDB `mavg/mstd(x,n)` 无 minPeriods 时前 n−1 行输出部分窗口值；带 minPeriods（`mstd(x,5,5)`）不满则 null。Rust 端用 row-based `VecDeque`（同 candidates.rs 的 State，不用 core24 的日历对齐 Ring），停牌日缺失即窗口压缩——与 DolphinDB 行为一致。
- **并行模型**：因子 5/8/10/29 含当日横截面计算，跟随 v3 模式——块内强制 `threads_per_job=1`（启动时校验并 bail），保证线程/块布局不影响输出。
- **warmup**：25 个交易日（最大跨日窗口 20 天 + 余量；warmup 日不写文件，机制照旧）。
- **输出**：`writer::write_day_dynamic` + `Manifest::new_named("dos_minute_v1", ...)`，收尾像 v3 一样产出 `quality_report.json`。

## 文件级改动

1. **`crates/quant-minute-factor/src/loader.rs`**：`Bar` 增加 `high: f64, low: f64` 字段；投影列加 `high, low`（canonical lake 已有这两列，已验证）；沿用现有价格校验（finite、>0）。现有 core24/candidates/v3 不读这两列，行为不变。
2. **`crates/quant-minute-factor/src/dos_candidates.rs`**（新建，主体约 1500–2000 行）：
   - `pub const N: usize = 31; pub const NAMES: [&str; N]`、`formulas()`（每个因子附 .dos 原式与对齐说明）、`pub fn run(args: BuildArgs)`（复制 v3 骨架：warmup 25、单线程块、manifest、quality_report）。
   - 模块内统计工具（现有代码没有的）：erf 正态 CDF、Student-t CDF（不完全 Beta 连分数，df=240）、`ols_t_f`（6 回归元正态方程 + 高斯消元解 (X'X)⁻¹ → 截距 t 值、滞后项 t 值、ANOVA F）、样本 std、总体 covar、wavg、kurtosis、横截面 percent-rank、`aggrTopN`/`ifirstHit`/`cumsum` 语义的小工具。
   - 按家族组织实现（共享中间件，最大化复用）：
     - F1 相关性（3,13,16,17,18,31）：共用 `corr` + lag/20日同时刻调整量装饰；
     - F2 熵（7,11）；
     - F3 CDF 主动占比（20,21,22,23）：`sum(Amount·w(x))/sum(Amount)` 骨架，w 可插拔；
     - F4 模糊性（25,26,29）：`fuzziness=mstd(mstd(ret,5,5),5,5)` 共用，29 加二阶段截面修正（10日 mstd + s1/s2 缩放）；
     - F5 支撑区域（27,28,30）：同价聚合→支撑点→|Δprice| 排序 cumsum≥0.5 ifirstHit 完整管线，三因子仅聚合与差值不同;
     - F6 OHLC 波动率协方差（12,15）；
     - F7 耀眼（9,14）：ΔVol>mean+std 阈值共用；
     - F8 OLS（10,19）：共用 retTB 构造（ΔV 及 1–5 阶滞后、index 5..=239）；
     - F9 K线形态（1,2,6）；
     - F10 截面排名矩（8）：分钟级 (date,minute) 横截面 rank → mean/std + kurtosis；
     - F11 时间结构（4,24）。
   - `State`：per-stock `VecDeque<Box<[f64;241]>>`（amount 曲线，因子 3/13 的 20 日同时刻窗口）、per-stock 残差/日频 Value 的短 VecDeque（因子 5、29）、按需记录当日截面中间量。
3. **`crates/quant-minute-factor/src/main.rs`**：`mod dos_candidates;` + `run_build` 增加 `dos_minute_v1` 分支 + `--factor-set` 帮助文本更新。
4. **文档**：新增 `docs/research/dolphindb_minute_factor_replication.md`——31 因子映射表（.dos 函数名→Rust 列名→公式）、时间窗/列映射决策、bug 修正与 quirk 保留清单、DolphinDB 语义对齐说明（aggrTopN、rank、kurtosis 口径等）。

## 测试与验收

- **单元测试**（内嵌 `#[cfg(test)]`，风格同现有）：
  - 每个家族至少 1 个手算小样本用例（构造 5–10 根合成 bar，逐步手算对照）；
  - 正态 CDF 与已知分位点对拍（如 Φ(1.96)≈0.975）；t(240) CDF 与正态近似差 < 1e-2 校验；OLS t/F 用可解析的小例子对拍；
  - loader 高低价投影 + 现有 loader 测试不回归；
  - NAMES 唯一性、warmup 日不写出、块布局不变性（复用现有测试模板）。
- **现有 sets 回归**：loader 改动后跑 core24 与 ohlcv_candidates_v1 各一个小区间，确认输出与改动前逐值一致（它们不消费 high/low）。
- **真实数据验收**：对一段真实区间（如一个月）跑 `cargo run -p quant-minute-factor -- build --factor-set dos_minute_v1 ...`，检查 quality_report.json 各列 null 率合理（尤其需要 20 日预热与截面成分覆盖的列）、无 NaN/Inf、行按 ts_code 排序。
- 不修改生产脚本 `scripts/produce_raw_candidate_factors.py`（研究性数据集，验证后再决定是否入生产，作为后续工作）。

## 风险与实现时校准点

- 本机无 DolphinDB，无法与 .dos 输出数值对拍；一致性靠公式忠实翻译 + 单元测试。以下 DolphinDB 语义以官方文档为准在实现时校准并固化到测试：`aggrTopN` 参数顺序（按代码上下文推断为"按 valueCol 排序返回 sortCol"，即因子 4 的 tideNum 为 adjVol 最大处行号）、`rank(percent=true)` 的 tie 处理与 (0,1] 区间、`kurtosis` 默认口径（因子 8）、`ols` mode=1/2 输出布局。
- 因子 3/13/5 在上市不足 20 天时按 DolphinDB 部分窗口语义出值（非 null），与现有 core24 的"≥10/20 天才出值"惯例不同——按 .dos 语义复现并在文档标注。
